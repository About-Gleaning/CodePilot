# 执行上限与统一消息提交

- 日期：2026-09-17。
- 工作项：CODE-61；本轮只覆盖执行上限与追加输入，不代表六阶段计划全部完成。
- 产品选择：停止后在原 Session 人工发送开启新 Run；不增加暂停状态、独立任务模型、工具检查点或自动重放。

## 发送协议

继续使用 `POST /api/agents/{agent_id}/runs`。HTTP 只依赖 Manager；`submit_message` 处理幂等与分流，`start_run` 保持只启动职责。

| 当前情况 | 结果 |
| --- | --- |
| 没有 Session | 创建 Session 并启动 Run |
| Session 空闲 | 原 Session 新 Run |
| Session 正在运行 | 追加消息并返回原 Run，不重新占用容量 |
| 等待人工、正在停止或关闭 | 409，消息未接收，前端保留草稿 |
| expected_run_id 与当前活动 Run 不同 | 409，不能意外创建新执行 |
| 已成功提交的请求重试 | 返回原 Run 和原消息回执，即使已经结束或服务重启 |

返回保留 `ref`、`status` 等字段，增加 `submission`：`mode=started/appended`、`message_id`、`status=accepted/pending/included`。追加回执含接收顺序；纳入后还含消费 Run 和轮次。已纳入只表示进入本地请求上下文，不能据此判断远端成功或完成任务。

幂等键为用户 ID 加 `client_request_id`，指纹涵盖 Agent、Session、正文、图片内容摘要、模型与思考参数、用户 metadata 和预期 Run。先查原发送结果，再检查当前执行状态。同 ID 不同请求冲突；追加不能改变当前模型，显式不匹配必须拒绝。

## 持久化与恢复

追加接收事件写入原 Session JSONL，包含原 Run 归属、请求指纹、消息 ID、接收顺序和受控消息结构，flush/fsync 成功后才入队并响应。图片复用既有路径、大小、MIME 和归属校验；JSONL 只保存文件信息，不含 base64。公开回执去除本地附件定位，使用现有受控预览 URL。

纳入记录同样追加并持久化，回放按消息 ID 重建最新状态；准备阶段进入内存但尚未纳入的消息不会成为已纳入历史。旧待处理消息在下一次人工发送时置于新输入之前，纳入记录保存相对位置，保证重启回放顺序一致。

首次发送时按用户历史重建追加幂等索引，仅缓存回执元数据；运行中不反复读取历史。重启保持原活动 Run 取消，不自动执行待处理输入或旧工具。沿用既有 JSONL 读取失败策略，损坏文件不能当作空历史继续。

## 决策与收尾边界

1. SessionInbox 的短锁串行接收、批次选取、进入人工等待、关闭与正常结束判定；锁不跨模型或工具调用。
2. 每次主 Agent 决策准备先选取此刻待处理消息，再加入上下文。准备期间新收到的消息留到下一次准备。
3. 压缩保护本批新输入原文，随后执行 Hook 和请求构造；准备失败仍为待纳入，通过消息 ID 防止再次插入。
4. 构造请求后持久化纳入记录、发布 Session SSE，再调用模型。当前子 Agent 使用独立上下文，不受主 Agent 追加改写。
5. 正常结束前短锁检查待处理消息；存在则继续下一轮。停止、失败、轮数上限优先，不因为追加重置轮数。

达到轮数上限为 `CANCELLED/max_iterations`。最后允许的一轮正常完成且没有待处理输入时仍为 `COMPLETED`。原因贯通 Session 生命周期、Run、历史回放与页面；子 Agent 返回明确失败结果，定时 worker 保留取消终态和上限原因。

## 前端与性能

- 详情页与看板沿用同一发送 URL，携带已观察到的 Run 身份；不确定网络结果复用原请求标识和请求内容。
- 追加回执不重建活动 Run、不重置开始时间、不清空生成文本。按消息 ID 合并回执，已纳入不能被较晚的待纳入 HTTP 响应覆盖。
- 生命周期 SSE 优先于延迟 HTTP；新 Run 开始事件可恢复活动身份。快速切换沿用 generation、AbortController 和事件归属校验。
- 待处理队列最多 20 条，字典入队摊销 O(1)，批次选取和出队 O(k)，额外空间 O(k)。消息去重和回放锚点各单次扫描当前上下文 O(n+k)，只在有待处理消息时执行；不为每条消息重复扫描历史。
- 用户首次发送的历史索引重建成本随已有历史增长；这是复用 JSONL 而不引入第二套持久索引的取舍。后续提交直接查询内存索引。
- 前端与公开回放最多保留 240 条回执，发送区最多展示 20 条并限制高度；每条正文和图片限制、Session SSE 队列 1000 上限继续生效。正文、附件和请求指纹不进入聚合事件。

## 验证

确定性测试使用临时存储和受控模型，不向真实用户或 Provider 发送任务。覆盖：

- 同接口启动/追加、十次并发相同请求只接收一次、原 Run 结束后及恢复后重试不重启、请求指纹冲突。
- 容量满仍可向自己活动 Run 追加，等待人工拒绝、模型不匹配拒绝、待处理 20 条上限、跨用户拒绝。
- 模型生成、工具、子 Agent、压缩准备期间追加；消息按批次消费，子上下文不被改写。
- 落盘失败不接收、准备失败保留待处理身份、人工继续顺序与去重、图片安全与公开回执路径过滤。
- 最后一轮正常结束、超限停止并保留待处理消息、子 Agent 不报成功、worker 不把取消映射为完成、压缩保留首轮新要求。
- SSE 先于 HTTP 的状态合并、保留流式文本与开始时间、新 Run 开始事件早于 HTTP、既有重连与切换回归。
